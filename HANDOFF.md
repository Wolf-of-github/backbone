### 🔄 Architecture Decision: Service-Level Authentication

**Key change from initial plan:** Kong does NOT verify JWT tokens. Instead:
- Kong routes all `/api/*` requests to backend services without authentication
- Each backend service includes `services/common/authContext.js` middleware
- Services verify `Authorization: Bearer <token>` headers themselves
- This provides maximum service autonomy and flexibility

**Rationale:**
- Simpler Kong configuration (declarative routing only)
- Backend services can implement custom auth logic if needed
- No tight coupling between gateway and auth mechanism
- Easier to test services independently

## How to Deploy from Scratch

### Prerequisites
- Linux host (Ubuntu 22.04+ or similar)
- Docker installed and running
- `kubectl`, `jq`, `openssl` available
- `.env` file configured (copy from `.env.example`)

### Full Deployment (Phase 0 → 3)

```bash
# Phase 0: Cluster substrate
make phase0          # cluster -> base -> secrets -> verify

# Phase 1: Data layer
make phase1          # data -> verify-phase1

# Phase 2: Edge (Kong + ping + frontend)
make phase2          # edge -> verify-phase2

# Phase 3: Authentication
make phase3          # auth -> verify-phase3
```

Each phase runs its verification gate. If all pass, the platform is ready.

### Accessing the Platform

Once deployed:

```bash
# Get Kong NodePort
kubectl -n platform get svc kong-proxy

# Access in browser (replace with your node IP)
http://<node-ip>:30080/
```

You'll see the login page. Register a new account to test authentication.

### Testing Authentication

```bash
# Register a user
curl -X POST http://<node-ip>:30080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"testpass123"}'

# Login
curl -X POST http://<node-ip>:30080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"testpass123"}'
# Returns: {"accessToken":"...","refreshToken":"..."}

# Access protected route
curl http://<node-ip>:30080/api/ping \
  -H "Authorization: Bearer <accessToken>"

# Get user info
curl http://<node-ip>:30080/api/auth/me \
  -H "Authorization: Bearer <accessToken>"
```

### Protecting New Services

To add auth to a new backend service:

1. Add `jsonwebtoken` to `package.json` dependencies
2. Copy shared middleware in Dockerfile:
   ```dockerfile
   COPY --chown=appuser:appgroup services/common ./src/common
   ```
3. Use middleware in routes:
   ```javascript
   const { requireAuth, requireRole, assertOwnership } = require('./common/authContext');

   app.get('/api/resource', requireAuth, (req, res) => {
     // req.user = { id, email, roles }
     res.json({ user: req.user });
   });
   ```

## Known Issues & Limitations

### Current Limitations
- **No TLS/HTTPS** - Tokens currently ride HTTP (Phase 5 will add cert-manager + Let's Encrypt)
- **Single MongoDB/Redis replicas** - No HA yet (multi-replica comes later)
- **No persistent volumes for local-path** - Data survives pod restarts but not node loss
- **No backup automation** - Manual backup procedures only (Phase 5+)
- **No monitoring/observability** - No Prometheus/Grafana yet (Phase 5+)

### Phase 3 Specific Notes
- Access tokens expire in 15 minutes by default - adjust `JWT_ACCESS_EXPIRY` if needed
- Refresh tokens are single-use - old token invalidated on each refresh
- Password validation: minimum 8 characters, no complexity requirements
- No email verification - users can register with any email format
- No password reset flow - requires manual intervention currently
- No rate limiting on auth endpoints - could be DoS target

### Troubleshooting

| Issue | Solution |
|-------|----------|
| Auth pods stuck `Pending` | Check MongoDB/Redis secrets exist in `app` namespace: `kubectl -n app get secrets` |
| Login returns 500 | Check auth logs: `kubectl -n app logs -l app=auth` |
| `/api/ping` returns 401 with valid token | Ping didn't rebuild with auth - run `make auth` again |
| "Cannot verify signature" errors | JWT keypair mismatch - check `.secrets/jwt/` exists and `jwt-keypair` secret is mounted |
| Frontend shows "Network Error" | Check Kong is routing to auth service: `kubectl -n platform get cm kong-declarative-config -o yaml` |
